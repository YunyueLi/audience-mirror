# 产品需求文档：Audience Mirror Media Environment

版本：MVP PRD v0.4
状态：Proposed
日期：2026-08-20

## 1. 一句话定位

Audience Mirror 是现实之前的多模态人群实验平台。本 PRD 定义它的首个 Media Environment：目标受众 Agent 按时间顺序体验未发布叙事内容，团队从逐时个体 Trace、内容理解、文化解释、分群差异和版本对比中发现问题，再用同任务真人反馈校准。

首版只实现 Media，不同时建设通用消费者、Web／App、游戏和社会情境运行时；这是交付顺序，不是 Audience Mirror 的长期产品边界。

人话标语：

> 在发布前，先看见目标观众在哪里看懂、动心和离开。

## 2. 产品目标

### 2.1 MVP 要证明的事

1. 顺序体验能比“摘要后问一轮”找到更多与真人一致的问题。
2. 聚合结论能下钻到具体素材时点和个体状态，内容团队能据此采取行动。
3. 相同 Audience Panel 可公平比较两个版本，且结论在重复运行中基本稳定。
4. 少量真人结果能显式暴露模型偏差；只有独立校正／封存样本充分时才进入数值校准。
5. 8—20 分钟素材的全链路成本和耗时允许日常迭代。
6. 开放 Persona／Eval 运行时能承接 Persona 与基础 Trial 能力；本轮新增 Media Environment、Trace 与校准，并沉淀可被其他 Environment 复用的公共合同。
7. 大 Persona 池、完整 Deep Trace、快速 Sweep 和 Population Projection 可以分层运行并分别解释。
8. 报告能分开素材事实、模拟个体反应、文化／身份解释、行为意向和不同类型真人参照，不用单一“情绪分”混合因果。
9. 实验能冻结观看发生时的接受语境和信息截止时间，并把盲测内容反应、显式语境场景与发布后观测分开。

### 2.2 MVP 不证明的事

- Agent 可以替代真人研究；
- Agent 数量具有统计代表性；
- 模型能准确预测票房、收入、留存或真实购买率；
- 一个原型可泛化到所有内容品类、国家和文化；
- 群体讨论自然产生的共识等于真实口碑。
- 眼动、脑电或其他生理信号可以单独证明观众喜爱、文化认同、传播动机或付费意愿。
- 模型能从内容本身稳定预测戏谑爆红、社交黑天鹅或发布后市场路径。

## 3. 首个客户与首个使用场景

### 3.1 理想首客

首客是一家内容平台、制作公司或 IP 商业化团队，具备：

- 一个仍可调整的 8—20 分钟叙事片段、粗剪或两版营销素材；
- 明确的目标受众分层；
- 已有 IP／用户资料；
- 一次两到四周内必须做出的版本决策；
- 既有真人问卷／访谈，或愿意新招 10—20 位真人盲测；
- 能确认素材授权、数据驻留和删除要求。

首个采购角色通常是内容策略／用户研究负责人，业务共同决策者是制片、IP、发行或营销负责人。

### 3.2 首个 Job-to-be-Done

> 我有两个可以发布的版本，仍能改动一轮。我想在不扩大泄密面的前提下，知道哪个版本更容易被各目标人群看懂、记住和愿意继续了解，并定位导致差异的具体时点。

### 3.3 使用时机

| 阶段 | 素材 | 主要问题 | MVP 支持 |
| --- | --- | --- | --- |
| 概念／剧本 | 剧本、分镜、animatic | 角色、设定、叙事与受众预期 | P1，先以文本时间轴兼容 |
| 粗剪／片段 | 8—20 分钟视频 | 理解、节奏、情绪、角色关系、放弃风险 | P0 |
| 营销 | PV、预告、片花、主视觉 | 信息传达、记忆点、兴趣与下一步行为 | P0 |
| 发布前真人研究 | 同一素材与人群 | Agent 与真人差异、需补访问题 | P0 |
| 完整长片 | 60—120 分钟视频 | 全片节奏、角色弧、结局 | P2 |
| 游戏内容 | 皮肤、Battle Pass、商城、玩法录像、原型 | 审美、价值感、理解与购买链路 | P1 |
| 游戏 Build | 可运行客户端 | 操作、玩法、功能、留存 | P2／P3 |

## 4. 核心概念

| 概念 | 定义 |
| --- | --- |
| Project | 一个内容研究项目，包含素材、受众、问题、实验和报告 |
| Asset | 视频、音频、脚本、字幕、分镜、图片或可点击原型 |
| Variant | 同一决策对象的一个版本；A/B 必须有独立版本 ID 与哈希 |
| Timeline | 从镜头到场景、事件和叙事段落的分层多模态时间轴 |
| Persona Universe | 可检索的 Persona 记录池及其来源、许可、覆盖、索引与版本；记录尚未等于已执行 Agent |
| Audience Panel | 明确来源、分层、配额、Persona 和限制的模拟受众集合 |
| Persona | 单一受众 Agent 的稳定背景、偏好、约束、知识和关系 |
| Interpretive Frame | 某个 Persona 用来理解内容的文化参照、媒介经验、身份语境或社群语言；必须标记数据来源与不确定性，不能由人口标签自动推断 |
| Reception Context | 观看当时已知的外部信息与社会条件，如独立盲测、共同观看、公开口碑、社群戏谑框架或争议；属于 Experiment，不是 Persona 的固有属性 |
| Participation Mode | 观众当前是沉浸、分析、戏谑、共同体验、实用消费还是获取社交货币；允许并存和变化，必须带行为／语言证据，不设总分 |
| Context Scenario | 明确注入一组外部社会线索的敏感性实验；输出是“若在该语境下”的条件反应，不是对语境会否真实发生的预测 |
| Viewing Session | 某 Persona 对某一 Variant 的一次隔离顺序体验 |
| Deep Trace | 完整顺序体验、长期记忆、行为与逐时证据的高保真 Session |
| Broad Sweep | 只使用摘要或少量关键检查点的低成本结构化 Persona 运行 |
| Population Projection | 用规则、校准响应面或小模型对大 Persona 池做场景投影，不逐条生成长文本 |
| Trace Event | 某时点的观察、状态变化、行为、反馈和证据引用 |
| Experiment | 固定素材、面板、模型、Prompt、种子和问题的一次可复现运行 |
| Human Anchor | 与实验同任务、同素材、同分群的真人反馈 |
| Calibration Profile | 在特定任务、品类和人群上由真人参照得到的校正与误差说明 |

## 5. 输入

### 5.1 必需输入

1. **素材**
   - MP4／MOV 视频；
   - 可选字幕、对白稿、剧本、角色表和时间码；
   - 至少一个 Variant；A/B 研究需要两个。
2. **研究 Brief**
   - 要做出的决策；
   - 预注册问题和指标；
   - 已知假设；
   - 禁止模型获知的信息；
   - 实验的信息截止时间、Reception Context、结果盲法状态，以及 Context Scenario 的来源与哈希。
3. **Audience Spec**
   - 目标人群、分层和配额；
   - IP 熟悉度、品类使用、观看习惯和消费约束；
   - 当研究问题需要时，加入明确来源的媒介经验、文化参照、社群语言与身份语境；
   - Persona 数据来源与许可；
   - 不确定或缺失字段。
4. **安全与权利**
   - 素材权利状态；
   - 允许的模型与区域；
   - 保留期限；
   - 可下载／可分享范围。

### 5.2 可选但强烈建议

- 既有真人问卷、访谈编码或行为数据；
- 获得独立授权、工具版本和时间同步信息的眼动或生理参照；
- 历史同类素材的真实表现；
- 业务方自己的评价量表；
- 角色／世界观资料；
- 版本变更清单；
- 需要重点保护的敏感片段。

### 5.3 禁止输入

- 没有处理授权的影视、游戏或个人资料；
- 未经同意的个人身份、眼动、生理或交易明细；
- 为了“丰富 Persona”而拼接的真实个人私密档案；
- 无法确认来源和许可的受众数据库。

## 6. 用户工作流

### 6.1 创建实验

1. 新建 Project，写明当前必须做出的具体决策。
2. 上传一个或多个 Variant，系统计算内容哈希并生成低清代理文件。
3. 选择数据处理模式：本地／VPC／允许的第三方模型。
4. 导入字幕、剧本和角色表；系统标记哪些内容来自用户、哪些由模型推断。

### 6.2 审核多模态时间轴

1. 系统自动完成镜头、场景、对白、OCR、角色、动作、音乐和关键事件解析。
2. 研究者查看 Timeline，合并／拆分场景，纠正角色和事件。
3. A/B 实验先对齐相同场景和版本特有片段。
4. 时间轴冻结后生成版本号；实验只能引用冻结版本。

### 6.3 建立 Audience Panel

1. 选择三个以内的核心分层。
2. 从已审计的 Persona Universe 检索候选；缺口才用明确规则补充合成 Persona。
3. 设置每层目标画像、Persona 来源和禁止推断字段。
4. 选出每层 4—6 个 Deep Persona；研究者检查是否重复、刻板或不合理。
5. 系统显示 Pool 与执行 Cohort 的覆盖矩阵和缺口，不提供“代表全体人口”的默认标签。

### 6.4 选择执行层

1. Deep Trace 默认运行 12—18 个 Persona，性能允许时扩至 32。
2. Broad Sweep 默认约 100 个 Persona，只接受冻结摘要或预注册关键检查点。
3. Population Projection 可展示 10k+ 记录的场景覆盖，但不逐人调用 LLM，也不生成伪访谈。
4. 研究者可以把 Sweep 中的异常、冲突或高不确定 Persona 升级为 Deep Trace。
5. 界面分开显示 Pool Records、Deep Traces、Sweep Runs、Projected Records、Stability Runs 和 Human Participants。

### 6.5 运行隔离观看

1. 每个 Persona 在独立 Session 中从时间零开始。
2. Runtime 按 Timeline 事件逐步暴露内容，未来片段不可检索。
3. Agent 更新理解、预期、情绪代理量、角色好感、记忆和行为意向。
4. Agent 可产生继续、标记困惑、请求回看、跳过、放弃、记住、考虑分享等动作。
5. 所有状态变化写为结构化 Trace；普通时段可以静默，不强制每秒“表演反应”。

### 6.6 聚合与版本比较

1. 先聚合独立 Session，不引入群体互动。
2. 生成问题卡、分群差异、时间曲线、角色弧和版本 Delta。
3. 每条结论显示支持者、反对者、证据和校准状态。
4. 版本比较采用隔离面板或反平衡顺序，避免先看 A 污染 B。

### 6.7 可选群体讨论

1. 只在独立判断完成后启动。
2. 保存讨论前观点、讨论消息、观点变化和影响来源。
3. 讨论结果单独命名为 Social Response，不与 Independent Response 混算。
4. MVP 可做 3—5 人小组演示，不把传播规模作为验收目标。

### 6.8 可选接受语境实验

1. 默认主结果来自 `independent_blind`，Agent 不知道真实市场表现与事后评论。
2. Context Scenario 只注入预注册的社会线索，例如“朋友群正在戏谑讨论”，并保留种子来源、时间与哈希。
3. 同一 Persona 的盲测与语境条件必须用隔离 Session 或反平衡设计，防止记忆污染。
4. 报告只呈现 Context Delta、Participation Mode 变化和反例，不将条件场景写成真实发生概率。
5. 已知结果的历史案例只能做回溯和泄漏测试；要声称前瞻价值，必须使用事前资料或新素材封存验证。

### 6.9 加入真人校准

1. 导入同素材真人评分、逐时标记或访谈问题编码。
2. 系统盲对齐 Agent 与真人结果。
3. 生成一致项、Agent-only、Human-only 和冲突项。
4. 四周公开 Demo 的 8—12 位真人只用于探索性问题集、时点和报告可用性，不拟合校正器，也不验证三分群。
5. 只有预注册样本计划包含独立校正集与封存验证集时，才对有足够数据的指标拟合校正；其余继续标记为未校准。
6. 报告保留原始模拟值与校正值，不能覆盖或擦除差异。

## 7. 核心输出

### 7.1 决策摘要

只回答预注册问题，最多包含：

- 推荐进入下一轮的版本及证据强度；
- 三个最需修正或真人验证的问题；
- 受影响的人群；
- 最关键的分歧；
- 本次结果的校准状态、成本和限制。

若证据不足，摘要必须允许输出“无法判断”。

### 7.2 逐时体验地图

时间轴显示以下可开关轨道：

- 内容事件与版本变更；
- 模型估计的参与／注意代理量；
- 情绪效价与唤醒代理量；
- 理解／困惑；
- 角色好感和关系理解；
- 记忆形成与遗忘风险；
- 跳过／放弃／分享／付费考虑；
- 真人参照；
- 运行间波动。

“注意力”“情绪”“购买”默认带有 Simulated 或 Predicted 标签；没有真人校准时禁止使用“真实注意力曲线”等措辞。

### 7.3 问题卡

每张问题卡必须包含：

- 清楚的问题陈述；
- 发生的 Variant 与时间范围；
- 受影响分群；
- 支持 Trace 数和反对／无感 Trace 数；
- 代表性画面、对白、音频或 UI 证据；
- 可能机制与替代解释；
- 置信与校准状态；
- 建议的最小改动或真人追问；
- 可展开的全部个体 Trace。

### 7.4 Audience Segment 对比

显示分群之间的：

- 理解断点；
- 角色认同；
- 预期落差；
- 关键记忆点；
- 继续／放弃风险；
- 分享语言与传播钩子；
- 付费考虑因素。

默认显示分布与个体点，不只显示平均值。

### 7.5 Variant Diff

每个差异都关联：

- 版本变更片段；
- 同一 Panel 的反应 Delta；
- 方向是否在重复运行中稳定；
- 真人是否同向；
- 是否可能来自模型随机性或顺序污染。

### 7.6 Interpretive Divergence

对文化语境明显的内容，报告另行展示：

- 同一事件在不同 Persona 中被读为幽默、冒犯、认同、戲仿、反抗或无感的差异；
- 这些解释依赖的文化参照、先验知识和具体素材证据；
- 少数解释、组内分歧和换模型后的翻转；
- 对应的真人访谈编码；没有 Human Anchor 时只标记为未校准解释假设。

这一输出不设“文化共鸣总分”，也不用眼动或生理波峰自动推导身份认同。

### 7.7 Context Sensitivity 与 Participation Mode

当实验显式包含多个 Reception Context 时，报告显示：

- 盲测内容反应与各 Context Scenario 的差异；
- 观众是否从沉浸观看转向戏谑、合看、打卡或社交货币式参与；
- 触发模式变化的具体线索、个体 Trace、反例与运行波动；
- 哪些结论来自事前条件实验，哪些只是发布后观测。

Participation Mode 是带证据的多标签，不是“审美正常／异常”分类，也不能用事后已知热度反向填写。

## 8. 用户如何检查 Agent 的具体反应

### 8.1 从汇总下钻

用户点击任一曲线峰值或问题卡后，进入 Trace Inspector：

1. 左侧播放素材并定位到对应时间；
2. 中间显示画面、对白、声音与事件证据；
3. 右侧列出每位 Agent 在此之前的相关记忆、当前观察、状态前后变化、动作和简短决策依据；
4. 可以切换支持、反对、无感和未观察到的 Agent；
5. 可以继续向前／向后查看该 Agent 的完整 Session；
6. 可以与真人同时间点记录并排比较。

### 8.2 Trace 的解释边界

Trace 保存可展示的“观察与决策依据摘要”，不保存或伪造模型隐藏思维链。研究者看到的是结构化证据和状态变化，而非把长篇自言自语当作因果真相。

### 8.3 反例优先

任何聚合结论都必须提供：

- 最强支持案例；
- 最强反例；
- 与主结论冲突的 Persona；
- 没有足够证据的分群；
- 换模型或重复运行是否翻转。

## 9. 功能需求

### P0：原型必须具备

| ID | 需求 | 验收 |
| --- | --- | --- |
| P0-01 | 处理 8—20 分钟视频并生成分层 Timeline | 所有场景有时间码、来源与置信；可人工纠正和冻结版本 |
| P0-02 | 接入一种可运行模型，同时固化可替换能力接口 | 业务 Schema 不出现供应商专属字段；第二模型属于 P1 |
| P0-03 | 从已审计 Universe 检索／补充 3 个分层、12—18 个可审查 Deep Persona | 显示来源、许可、缺失、重复和分层覆盖 |
| P0-04 | 按顺序运行 Viewing Session | 未来事件不可访问；可重放同一实验配置 |
| P0-05 | 记录结构化 Trace | 通过 schemas/trace.schema.json 校验 |
| P0-06 | 逐时地图与个体下钻 | 任一聚合结论可在三次点击内到达证据和 Session |
| P0-07 | A/B 隔离与版本对齐 | 同一变更可查看两个版本的对应事件和反应 Delta |
| P0-08 | 导入探索性真人结果并生成 Convergence Map | 显示一致、仅 Agent、仅真人、冲突四类；保持 U0／U1，不拟合校正器 |
| P0-09 | 重复运行与成本面板 | 显示模型、Prompt、种子、耗时、tokens／费用和稳定性 |
| P0-10 | 素材权限与删除策略 | 每个 Asset 有权利状态、保留期限、访问日志与删除结果 |
| P0-11 | MatrAIx 固定版本 Adapter Spike | 可读取合规小型 Persona Pool、生成 Cohort／Trial 清单并把结果映射到本项目 Trace；失败时保留内置 Stub |
| P0-12 | 三层规模演示 | 12 个 Deep Trace、约 100 个 Broad Sweep 和 10k 无逐人 LLM Projection 分别显示调用、耗时、成本和证据等级 |
| P0-13 | 解释层与测量层分离 | Trace 与报告能区分内容理解、文化解释、行为意向、自报与眼动／生理 Human Anchor；不同类型不聚合成单一真值 |
| P0-14 | 接受语境与结果盲法可复现 | Run Manifest 记录 Reception Context、信息截止时间、outcome_blinded 和 Context Seed 哈希；报告不把语境条件结果写成市场概率 |

### P1：验证后加入

- 剧本／animatic 时间轴；
- 可点击原型事件流；
- 角色与关系图；
- 3—5 人观看后讨论；
- 报告批注、审核和导出；
- 企业自定义指标与校准 Profile；

- 中国本地模型与 VPC 路由；
- 盲测内容反应与预注册 Context Scenario 的敏感性对照。

### P2：不进入首轮

- 60—120 分钟完整影片的稳定生产化；
- 大规模社交传播；
- 游戏 Build GUI Agent；
- 真实眼动／生理设备实时接入；
- 自动改剪并直接发布；
- 票房、LTV 或 D1／D7 绝对预测；
- 从素材独立输入自动预测戏谑爆红、舆情黑天鹅或真实社会传播路径。

## 10. 多模态与群体智能的产品分工

| 层 | 产品贡献 | 首版呈现 |
| --- | --- | --- |
| 多模态理解 | 知道具体发生了什么，区分画面、声音、对白、音乐、角色和 UI | 可编辑 Timeline 与证据播放器 |
| 长程记忆 | 知道 Agent 在某时点已经看过、记住和误解了什么 | Session 记忆轨迹与理解变化 |
| Persona | 让同一素材在知识、偏好和约束不同的人身上产生可比较反应 | Audience Matrix 与个体 Session |
| 群体聚合 | 发现共同问题、分群差异和版本方向 | 问题卡、分布与 Variant Diff |
| 群体互动 | 探索讨论、从众和传播路径 | 独立结果之后的可选 Social Lab |
| 接受语境 | 区分内容本身反应、共同观看和社会线索带来的条件变化 | 可复现 Context Spec；敏感性报告属 P1 |
| 真人校准 | 把“合理语言”转成可度量的方向性证据 | Convergence Map、误差和适用范围 |

## 11. 非功能需求

### 11.1 可追溯

- 每条结果保留 Asset、Timeline、Persona、模型、Prompt、运行和证据 ID。
- 聚合器不能生成没有 Trace 支持的结论。
- 人工修改必须有作者、时间和前后值。

### 11.2 可复现

- 实验配置不可变；
- 记录模型版本与供应商；
- 支持缓存与相同配置重跑；
- 明确“模型服务升级后不保证逐字一致”，比较结构化结果而非文本。

### 11.3 安全

- 未发布素材默认私有；
- 原片与低清代理分开保存；
- 支持租户隔离、加密、最小权限、短留存和删除证明；
- 第三方模型路由必须显示传输范围；
- 素材内文本按不可信输入处理，防止 Prompt Injection。

### 11.4 性能与成本目标

原型目标而非现状承诺：

- 15 分钟视频首次 Timeline 构建在 30 分钟内完成；
- 12 个 Agent 的一次独立实验在 20 分钟内完成；
- 同一 Timeline 重跑只产生 Persona 体验成本；
- 客观 Timeline 只重解析变化片段；Persona Session 默认从最早变化事件重跑到片尾，除非能证明状态与记忆重新收敛；
- 单次公开 Demo 的模型直接成本目标低于 15 美元。

15 美元目标只对应 Deep Reference Workload：15 分钟、40—80 个 Event、12 个 Deep Trace、单模型、五次以内结构化重试，不含 Broad Sweep、第二模型、真人招募和人工编码。Broad Sweep 另设硬预算，超限时减少检查点或换小模型；10k Projection 不允许逐 Persona 调用 LLM。模型、价格日期、并发、采样密度与缓存命中必须随结果一起报告。

## 12. 成功指标

### 12.1 研究质量

- A/B 方向一致性；
- Human Top-K Recall 与 Precision@K；
- 时间点匹配；
- 分群排序一致性；
- 运行稳定性；
- 探索性 Human Convergence；校准误差属于后续 C1 研究；
- 无证据结论率。

定义与门槛见 [验证计划](04-validation-plan.md)。

### 12.2 产品使用

- 决策者是否能在 15 分钟内找到三个可行动问题；
- 聚合结论下钻率；
- 被研究者保存／分享的问题卡比例；
- 报告是否改变下轮真人研究问题或素材版本；
- 从上传到第一次可审查报告的时间；
- 客户是否愿意再次提交新版本。

## 13. 与 MatrAIx、Foreworld、MiroFish 的关系

### 13.1 MatrAIx

MatrAIx 是当前 P0 Persona／Eval 运行时复用候选：

- 复用 Persona 检索、Cohort、Task／Trial／Verifier、Telemetry 和成本账本；
- 本产品新增第五类 Media Environment、长程顺序状态、Timeline／Trace 和真人校准；
- 先以固定 Commit 外部 Adapter 接入，不把完整上游 Monorepo 或 Persona 1M 数据复制进本仓库；
- 代码 MIT 与 Persona 数据权利分别审查；公开 Coreset 在统一许可证和逐来源条款未核清前不默认商用或再分发；
- 同一任务至少保留内置 Stub／TinyTroupe 对照，避免将产品绑定到一个早期项目。

### 13.2 Foreworld

Foreworld 擅长现实证据、世界记忆、关系和社会推演。本产品可长期作为其 Scenario 垂直应用：

- Timeline 与 Viewing Runtime 由本产品维护；
- Audience 数据可选择映射到 WMG 的 Agent／关系语义；
- 观看后讨论与传播可通过版本化 GAIA Adapter 调用；
- Foreworld 的 Reality 主分支不接收未发布内容或模拟反应；
- 在 GAIA 合同稳定前，使用本仓库自带的小型模拟 Stub。

### 13.3 MiroFish

截至本次审查的公开 main，MiroFish 的核心是图谱、Persona、OASIS Twitter／Reddit 双平台模拟和 ReportAgent；没有完整视频时间轴与连续观看运行时。它可作为研究参考或独立服务适配对象。

公开仓库使用 AGPL-3.0。计划闭源时不直接复制或链接其代码；即使采用进程／API 边界，也要结合通信紧密程度和实际部署做单独许可评估。参见 [GNU AGPL](https://www.gnu.org/licenses/agpl-3.0) 与 [GNU FAQ](https://www.gnu.org/licenses/gpl-faq.en.html)。这不是正式法律意见。

## 14. 首版完成定义

MVP 只有在以下条件同时满足时才算完成：

1. 一部公开 8—20 分钟影片和两个同源营销 Variant 均跑通；
2. 所有聚合结论可下钻到个体 Trace 和多模态证据；
3. one-shot 与 sequential 两个技术实验臂可比较；
4. 至少 8—12 位真人完成同素材探索性盲测，结果保持 U0／U1；
5. 输出 A/B、问题命中、证据支持、稳定性、成本和限制；
6. 私密资料未进入仓库或不合规模型服务；
7. 没有任何页面把 Agent 数量显示成真实样本量或统计显著性。
8. Pool、Deep、Sweep、Projected、Stability 与 Human 六种计数严格分开；10k Projection 为零逐人 LLM 调用。
9. MatrAIx Adapter 的版本、许可证、失败回退和实际复用范围可核查。
10. 每次运行显示 Reception Context 和结果盲法状态；盲测内容反应不与语境条件反应混算。
